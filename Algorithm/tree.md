## 완전 이진 트리

- 왼쪽부터 순서대로 데이터가 쌓이는 트리 구조
- 배열로도 표현이 가능하다. 단, 트리를 구현할 땐 접근 편의성을 위해 0번째 인덱스는 사용되지 않고 `None` 을 넣는다.

### 배열구조에서 이진트리 노드에 접근하는 방법

- 왼쪽 자식의 인덱스 접근
   - `현재 인덱스 * 2`
- 오른쪽 자식의 인덱스 접근
  - `현재 인덱스 * 2 + 1`
- 부모의 인덱스 접근
  - `현재 인덱스 // 2`

실제 데이터를 예로, `[None, 8, 6, 3, 4, 2, 5]` 라는 배열을 트리 구조로 활용하고 위 공식으로 각 노드에 접근한다고 해봅시다.

- 6의 왼쪽 자식에 접근하려면 `2 * 2 =` 4번째 인덱스, 4에 접근!
- 6의 오른쪽 자식에는 `2 * 2 + 1 =` 5번째 인덱스, 2에 접근!
- 6의 부모 인덱스는 `2 // 2 =` 1번째 인덱스, 8에 접근!

```python
      8      Level 0
    6   3    Level 1
   4 2 5     Level 2  # -> 이진 트리 O 완전 이진 트리 O
```
위 배열을 트리구조로 시각화 해보면, 이렇게 생겼네요.

그런데, 이 완전 이진 트리 구조는 언제? 왜? 사용되는 걸까요?

## 힙

- 완전 이진 트리를 기본으로 하는 자료구조
- 데이터에서 최대/최소 값만 빠르게 찾기 위해 고안된 자료구조
- 이 자료구조는 항상 부모-자식 간의 대소관계(힙 속성)을 유지해야 하기 때문에 데이터가 적절히 정렬(반정렬 상태)되어 있다.

### 최대 힙(Max Heap)과 최소 힙(Min Heap)

- 힙은 부모-자식 간의 대소관계를 항상 만족시켜야 한다는 규칙이 있는데, 이 때문에 자식이 부모보다 크다면 `최소 힙`이 되고 반대의 경우라면 `최대 힙`이 된다.
- 이 규칙 덕분에 힙에서 데이터 삽입/삭제 등이 발생할 때마다, 자동으로 대소 관계를 재정렬하게 되어 힙에서의 데이터는 "반정렬" 상태를 보장할 수 있게 된다.

## BST(Binary Search Tree)

- 정렬된 트리이다. 모든 노드의 값은 왼쪽 자식노드의 값보다 크고, 오른쪽 자식노드의 값보다 작다.
- 검색/저장/삭제 시간 복잡도는 모두 O(log n)이다.
- 한쪽으로 치우친 트리(skewed)가 된다면 최악의 경우 O(n)이 될 수 있다.

```최악의 경우 예시
1 
 \
  2
   \
    3
     \
      4
```

## Self-Balancing BST

- 한쪽으로 치우친 트리(skewed)에 대한 단점을 보완하기 위해 탄생한 트리이며, 모든 노드의 좌우 자식트리의 높이 차가 ≤ 1 이다.
- 삽입/삭제 후 자동으로 트리를 재정렬하여 항상 O(log n) 성능을 보장한다.
- AVL 트리, Red-Black 트리 등 균형 이진 검색 트리를 구현하기 위한 여러가지 알고리즘이 있다.
